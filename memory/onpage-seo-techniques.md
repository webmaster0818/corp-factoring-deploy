# オンページSEO・個別テクニック

## titleタグ最適化

**重要性:**
- 最も重要なランキング要因の1つ
- CTR(クリック率)に直接影響
- SERPsでの見え方を決定

**ベストプラクティス:**
1. **長さ:** 30-35文字(日本語) / 60文字以内推奨
2. **キーワード配置:** 重要なキーワードは前方に
3. **ブランド名:** 末尾に追加(知名度がある場合)
4. **ユニーク性:** 各ページ固有のタイトル
5. **魅力的に:** クリックしたくなる表現

**避けるべきこと:**
- キーワードの詰め込み
- すべてのページで同じタイトル
- ブランド名だけ
- 「ホーム」「新着」など曖昧な表現

**例:**
```html
<!-- 良い例 -->
<title>Core Web Vitals完全ガイド - ページスピード最適化 | サイト名</title>

<!-- 悪い例 -->
<title>SEO,SEO対策,検索エンジン最適化,上位表示,Google対策</title>
```

**Googleの書き換え:**
- Googleがタイトルを自動変更することがある
- ブランド検索時
- タイトルが不適切な場合
- 検索クエリに合わせて

## メタディスクリプション

**重要性:**
- 直接的なランキング要因ではない
- CTRに大きく影響
- SERPsでの説明文

**ベストプラクティス:**
1. **長さ:** 120-130文字(日本語) / 155文字以内推奨
2. **要約:** ページ内容の簡潔な要約
3. **行動喚起:** 「詳しくはこちら」「今すぐチェック」など
4. **キーワード:** 自然に含める(太字表示される)
5. **ユニーク性:** 各ページ固有

**例:**
```html
<meta name="description" content="Core Web Vitalsの3つの指標(LCP、FID、CLS)を詳しく解説。
Googleランキング要因への影響、測定方法、改善テクニックまで網羅した完全ガイドです。">
```

**注意:**
- Googleが自動生成することもある
- 検索クエリに合わせて変更される
- 空白でも問題ない(自動生成される)

## 見出しタグ(H1-H6)

**階層構造:**
```html
<h1>メインタイトル</h1>
  <h2>セクション1</h2>
    <h3>サブセクション1-1</h3>
    <h3>サブセクション1-2</h3>
  <h2>セクション2</h2>
    <h3>サブセクション2-1</h3>
```

**H1タグ:**
- ページに1つ推奨(複数でも問題ないが非推奨)
- ページの主題を明確に
- titleタグと同じでも異なってもOK
- キーワード含める

**H2-H6:**
- 論理的な階層構造
- 飛ばさない(H2→H4はNG)
- コンテンツの構造化
- ユーザビリティ向上

**SEO効果:**
- 直接的ランキング要因
- コンテンツの理解促進
- フィーチャードスニペット獲得に有利

## URL構造

**ベストプラクティス:**
1. **シンプル:** 短く分かりやすく
2. **意味のある:** 内容が推測できる
3. **ハイフン:** 単語区切りは-(ハイフン)
4. **小文字:** 大文字小文字を混在させない
5. **日本語避ける:** 英数字推奨

**良い例:**
```
https://example.com/blog/core-web-vitals-guide/
https://example.com/products/blue-widget/
```

**悪い例:**
```
https://example.com/page.php?id=123&cat=456
https://example.com/コアウェブバイタル/
https://example.com/a/b/c/d/e/f/g/very-deep-page/
```

**ディレクトリ構造:**
- 階層は浅く(3-4階層まで)
- カテゴリ階層を反映
- パンくずリストと連動

## 画像最適化

**ファイルサイズ:**
- 圧縮必須
- WebP形式推奨
- 適切な解像度

**alt属性:**
```html
<img src="core-web-vitals.jpg" 
     alt="Core Web Vitalsの3つの指標を示す図">
```
- 必須項目
- 画像の内容を説明
- キーワード自然に含める
- スクリーンリーダー対応

**ファイル名:**
```
core-web-vitals-guide.jpg  ← 良い
IMG_1234.jpg  ← 悪い
```

**その他:**
- width/height属性指定(CLS対策)
- loading="lazy" 遅延読み込み
- srcset レスポンシブ画像

## 内部リンク

**重要性:**
- PageRank分配
- クロール促進
- ユーザビリティ向上

**ベストプラクティス:**
1. **アンカーテキスト:** 説明的に
2. **関連ページへ:** 自然な文脈で
3. **適量:** 過剰なリンクは避ける
4. **深い階層へ:** 重要ページへリンク

**アンカーテキスト:**
```html
<!-- 良い例 -->
<a href="/core-web-vitals/">Core Web Vitalsの詳しい解説</a>

<!-- 悪い例 -->
<a href="/core-web-vitals/">こちら</a>
<a href="/core-web-vitals/">クリック</a>
```

**サイト構造:**
- トップページから重要ページへ
- パンくずリスト
- 関連記事リンク
- サイトマップページ

## コンテンツ最適化

**キーワード配置:**
1. タイトルタグ
2. H1タグ
3. 最初の段落
4. H2-H3タグ
5. 本文中(自然に)
6. 最後の段落
7. alt属性

**キーワード密度:**
- 2-3%が目安(厳密ではない)
- 自然な文章が最優先
- 詰め込みは厳禁

**コンテンツの質:**
- オリジナル性
- 深さ・網羅性
- 最新性
- 正確性
- 読みやすさ

**文章長:**
- 長ければ良いわけではない
- 必要十分な長さ
- トピックによる
- ユーザーの意図を満たす

## リッチスニペット対策

**構造化データ種類:**
- Article
- FAQ
- How-to
- Product
- Recipe
- Review
- Video
- Breadcrumb

**FAQ構造化データ例:**
```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [{
    "@type": "Question",
    "name": "Core Web Vitalsとは？",
    "acceptedAnswer": {
      "@type": "Answer",
      "text": "Core Web Vitalsは..."
    }
  }]
}
```

**メリット:**
- 検索結果での視認性向上
- CTR向上
- トラフィック増加

**重要性:**
- ユーザビリティ
- 内部リンク構造
- 検索結果表示

**構造化データ:**
```json
{
  "@context": "https://schema.org",

  "itemListElement": [{
    "@type": "ListItem",
    "position": 1,

    "item": "https://example.com/"
  },{
    "@type": "ListItem",
    "position": 2,
    "name": "ブログ",
```

## ページネーション

**rel="next/prev"(廃止):**
- 以前は推奨
- 現在は不要

**現在の推奨:**
- 各ページに独自のtitle/description
- canonicalは自己参照
- 「全て表示」ページがあればそちらをcanonical

**ページネーションの種類:**
1. 番号付きページネーション
2. 「もっと見る」ボタン
3. 無限スクロール

**無限スクロール対応:**
- 各アイテムに固有URL
- History API使用
- サイトマップに全URL

## モバイル最適化(オンページ視点)

**ビューポート設定:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

**フォントサイズ:**
- 16px以上推奨
- タップターゲット 48x48px以上

**インタースティシャル:**
- 全画面ポップアップ避ける
- コンテンツ閲覧妨げない
- モバイルユーザビリティ重視

## まとめ: オンページSEOの本質

**従来:** キーワードを詰め込む
**現在:** ユーザーの意図を満たす

オンページSEOは「検索エンジンに理解させる」ことと
「ユーザーに価値を提供する」ことの両立。

技術的な最適化は基礎。
その上に立つのは質の高いコンテンツ。
