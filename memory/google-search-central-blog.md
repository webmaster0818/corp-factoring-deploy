# Google Search Central Blog 学習記録

## 学習期間: 2026-03-04 02:16〜02:30

### 学習目的

BEST-FIT運営とこれから複数の新規サイト構築のため、Google公式のSEO最新方針を深く理解する。

---

## 1. E-E-A-T (Experience, Expertise, Authoritativeness, Trustworthiness)

### E-E-A-Tの定義

**公式ドキュメント:** https://developers.google.com/search/docs/fundamentals/creating-helpful-content

**E-E-A-Tとは:**
Googleの自動ランキングシステムが使用する要素の組み合わせで、Experience (経験)、Expertise (専門性)、Authoritativeness (権威性)、Trustworthiness (信頼性) を示すコンテンツを特定する。

**Trust (信頼性) が最も重要:**
- 他の要素はすべて信頼性に貢献する
- コンテンツが必ずしもすべての要素を示す必要はない
- 経験を示すコンテンツ、専門性を示すコンテンツ、どちらも有益

**YMYL (Your Money or Your Life) トピック:**
- 健康、経済的安定、人々の安全、社会の福祉に大きな影響を与える可能性のあるトピック
- YMYLトピックでは、E-E-A-Tがさらに重視される

## 2. People-First Content (人のためのコンテンツ)

### People-First Contentの定義

**主な目的:**
検索エンジンのランキングを操作するためではなく、主に人々のために作成されたコンテンツ。

### 評価基準 (自己評価質問)

**コンテンツと品質に関する質問:**

1. コンテンツはオリジナルの情報、報告、研究、分析を提供しているか?
2. コンテンツはトピックの実質的、完全、包括的な説明を提供しているか?
3. コンテンツは明白なことを超えた洞察的な分析や興味深い情報を提供しているか?
4. 他のソースを参照している場合、単にコピーや書き換えを避け、実質的な付加価値と独創性を提供しているか?
5. メインの見出しやページタイトルは、コンテンツの説明的で役立つ要約を提供しているか?
6. メインの見出しやページタイトルは、誇張したり衝撃的な性質を避けているか?
7. ブックマークしたり、友人と共有したり、推奨したりしたいページか?
8. 印刷された雑誌、百科事典、書籍で見たり参照されることを期待するコンテンツか?
9. 検索結果の他のページと比較して、コンテンツは実質的な価値を提供しているか?
10. コンテンツにスペルや文体の問題はあるか?
11. コンテンツはよく制作されているか、それとも雑で急いで制作されたように見えるか?
12. コンテンツは大量の作成者によって大量生産されたり、外注されたり、大規模なサイトのネットワークに分散されて、個々のページやサイトがそれほど注意やケアを受けていないか?

**専門性に関する質問:**

1. コンテンツは、明確なソース、専門知識の証拠、著者やサイトの背景(著者ページやサイトのAboutページへのリンクなど)を通じて、信頼したくなるような方法で情報を提示しているか?
2. コンテンツを制作しているサイトを調査した場合、そのトピックについて信頼されている、または広く認められた権威であるという印象を受けるか?
3. このコンテンツは、トピックをよく知っている専門家や愛好家によって書かれたり、レビューされたりしているか?
4. コンテンツに簡単に検証できる事実の誤りはあるか?

## 3. Who, How, Why フレームワーク

### Who (コンテンツを作成したのは誰か)

**評価質問:**
- 訪問者にとって、誰がコンテンツを作成したかは明確か?
- 期待される場所で署名欄(byline)を掲載しているか?
- 署名欄は、著者に関する詳細情報にリンクしており、その背景や執筆分野についての情報を提供しているか?

**推奨:**
正確な著者情報(読者が期待する場所での署名欄など)を追加することを強く推奨。

### How (コンテンツはどのように作成されたか)

**評価質問(自動化/AI使用の場合):**
- 自動化(AI生成を含む)の使用は、開示やその他の方法で訪問者にとって明確か?
- 自動化やAI生成がどのように使用されてコンテンツが作成されたかについての背景を提供しているか?
- 自動化やAIがコンテンツ制作に有用であると見なされた理由を説明しているか?

**開示の重要性:**
誰かが「これはどのように作成されたのか?」と考える可能性がある場合は、開示を追加することを検討。

### Why (なぜコンテンツが作成されたか)

**最も重要な質問:**
なぜそもそもコンテンツが作成されているのか?

**正しいWhy:**
主に人々を助けるためにコンテンツを作成している。訪問者がサイトに直接来た場合に役立つコンテンツ。

**間違ったWhy:**
主に検索エンジンの訪問を引き付けるためにコンテンツを作成している = Googleのシステムが報酬を与えようとするものと一致していない。

## 4. Search Engine-First Content (避けるべき)

### 警告サイン

以下の質問のいくつかまたはすべてに「はい」と答える場合は、コンテンツの作成方法を再評価する必要がある:

1. コンテンツは主に検索エンジンからの訪問を引き付けるために作成されているか?
2. 多くの異なるトピックについて大量のコンテンツを制作して、その一部が検索結果でうまく機能することを期待しているか?
3. 多くのトピックについてコンテンツを制作するために広範な自動化を使用しているか?
4. 主に他の人が言っていることを要約しているだけで、あまり価値を追加していないか?
5. トレンドになっているように見えるという理由だけで物事について書いているか?(既存の視聴者のために書く場合は別)
6. コンテンツを読んだ後、読者は他のソースからより良い情報を得るために再度検索する必要があると感じるか?
7. Googleが好む単語数があると聞いたり読んだりしたため、特定の単語数に合わせて書いているか?(いいえ、そのような好みはありません)
8. 実際の専門知識なしにニッチなトピック分野に参入することを決めたが、主に検索トラフィックを得られると思ったからか?
9. コンテンツは、実際には答えのない質問(製品、映画、テレビ番組のリリース日が確認されていないのに、リリース日があると示唆するなど)に答えることを約束しているか?
10. コンテンツが実質的に変更されていないのに、ページが新鮮に見えるようにページの日付を変更しているか?
11. 新しいコンテンツをたくさん追加したり、古いコンテンツをたくさん削除したりしているのは、主にサイトが「新鮮」に見えることで検索ランキング全体に役立つと考えているからか?(いいえ、役立ちません)

## 5. Core Updates (コアアップデート)

**公式ドキュメント:** https://developers.google.com/search/docs/appearance/core-updates

### Core Updatesとは

年に数回、Googleは検索アルゴリズムとシステムに重要で広範な変更を加える。これをコアアップデートと呼ぶ。

**目的:**
検索者に役立つ信頼できる結果を提供するというミッションを確実に果たすため。

**特性:**
- 広範な性質
- 特定のサイトや個別のWebページをターゲットにしていない
- Web上のコンテンツが変化するにつれて、システム全体を評価・更新

### Core Updateの考え方(比喩)

レストランのトップ20リストを想像:
- 2019年に最初に作成したリスト
- 新しいレストランが登場
- 以前のレストランを再評価
- リストが変更される
- 順位が下がったレストランは必ずしも「悪い」わけではない
- 単に他のレストランがトップ20に入っただけ

### 対応方法

**小さな順位低下 (2位から4位):**
- 大幅なアクションを取る必要はない
- すでに良好なコンテンツを変更することは避ける

**大きな順位低下 (4位から29位):**
- より深い評価を実施
- [自己評価質問](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)を使用
- サイト全体(個々のページだけでなく)が、役立つ、信頼できる、人のためのコンテンツを提供しているかを確認

### 変更を加える際の注意点

**避けるべきこと:**
- 「クイックフィックス」的な変更(SEOに悪いと聞いたからページ要素を削除するなど)

**推奨されること:**
- ユーザーにとって意味があり、長期的に持続可能な変更に焦点を当てる
- コンテンツを意味のある方法で改善(書き直し、再構成など)
- コンテンツの削除は最後の手段(救済不可能な場合のみ)

### 効果が現れるまでの時間

- 改善を加えた場合、検索結果に効果が現れるまで時間がかかる可能性がある
- 数日で効果が現れる変更もあれば、数ヶ月かかることも
- システムがサイト全体が長期的に役立つ、信頼できる、人のためのコンテンツを生成していることを学習・確認する必要がある
- 数ヶ月経っても効果がない場合、次のコアアップデートまで待つ必要がある可能性
- ただし、小規模なコアアップデートは常に行われている(発表されないが、順位上昇の可能性あり)

## 6. Spam Policies (スパムポリシー)

**公式ドキュメント:** https://developers.google.com/search/docs/essentials/spam-policies

### スパムの定義

Google検索において、スパムとは、ユーザーを欺いたり、検索システムを操作してコンテンツを高くランク付けさせたりするために使用される技術を指す。

**検出方法:**
- 自動システムと人間によるレビュー
- ポリシーに違反するサイトは、結果で低くランク付けされるか、まったく表示されない可能性

### 主要なスパムポリシー

#### 1. Cloaking (クローキング)

**定義:**
検索ランキングを操作してユーザーを誤解させる意図で、ユーザーと検索エンジンに異なるコンテンツを提示する行為。

**例:**
- 検索エンジンには旅行先のページを表示し、ユーザーには割引薬のページを表示
- ユーザーエージェントが検索エンジンの場合のみ、テキストやキーワードを挿入

**例外:**
- Paywallやコンテンツゲーティングは、Googleがゲート内の完全なコンテンツを見ることができ、[Flexible Sampling guidance](https://developers.google.com/search/docs/appearance/flexible-sampling)に従っている場合、クローキングとは見なされない

#### 2. Doorway Abuse (誘導ページの不正使用)

**定義:**
特定の類似した検索クエリにランク付けするためにサイトやページが作成され、ユーザーを最終目的地ほど有用ではない中間ページに誘導する。

**例:**
- 特定のクエリのリーチを最大化するために、URLやホームページにわずかなバリエーションを持つ複数のWebサイトを持つ
- 特定の地域や都市をターゲットにした複数のドメイン名やページを持ち、ユーザーを1つのページに誘導
- 訪問者を実際に使用可能な部分に誘導するためにページを生成

#### 3. Expired Domain Abuse (期限切れドメインの不正使用)

**定義:**
期限切れドメイン名を購入し、ユーザーにほとんど価値を提供しないコンテンツをホストすることで、主に検索ランキングを操作することを目的として再利用する。

**例:**
- 以前政府機関が使用していたサイトでのアフィリエイトコンテンツ
- 以前非営利の医療慈善団体が使用していたサイトでの商業医療製品の販売
- 以前小学校だったサイトでのカジノ関連コンテンツ

#### 4. Hacked Content (ハッキングされたコンテンツ)

**定義:**
サイトのセキュリティ脆弱性により、許可なくサイトに配置されたコンテンツ。

**例:**
- コードインジェクション: 既存のページに悪意のあるJavaScriptを直接挿入、またはiframeに挿入
- ページインジェクション: セキュリティ欠陥により、スパムや悪意のあるコンテンツを含む新しいページを追加
- コンテンツインジェクション: 既存のページを微妙に操作し、検索エンジンには見えるが、ユーザーやサイト所有者が気づきにくいコンテンツを追加
- リダイレクト: 一部のユーザーを有害またはスパムページにリダイレクトする悪意のあるコードを注入

#### 5. Hidden Text and Link Abuse (隠しテキストとリンクの不正使用)

**定義:**
人間の訪問者には簡単に見えない方法でページにコンテンツを配置し、検索エンジンのみを操作することを目的とした行為。

**例:**
- 白い背景に白いテキストを使用
- 画像の後ろにテキストを隠す
- CSSを使用してテキストを画面外に配置
- フォントサイズまたは不透明度を0に設定
- 小さな文字(段落の途中のハイフンなど)のみをリンクすることでリンクを隠す

**ポリシー違反ではないもの:**
- アコーディオンやタブ形式のコンテンツ
- スライドショーやスライダー
- ツールチップ
- スクリーンリーダー向けのテキスト

#### 6. Keyword Stuffing (キーワードの詰め込み)

**定義:**
Google検索結果のランキングを操作する試みとして、Webページにキーワードや数字を詰め込む行為。

**例:**
- 実質的な付加価値のない電話番号のリスト
- Webページがランク付けしようとしている都市や地域をリストするテキストのブロック
- 不自然に聞こえるほど同じ単語やフレーズを繰り返す

#### 7. Link Spam (リンクスパム)

**定義:**
主に検索ランキングを操作する目的でサイトとの間にリンクを作成する行為。

**例:**
- ランキング目的でリンクを売買(お金、商品、サービスの交換)
- 過度なリンク交換(「私にリンクして、私があなたにリンクする」)
- 自動プログラムやサービスを使用してサイトへのリンクを作成
- サービス利用規約や契約の一部としてリンクを要求(サードパーティに[リンクを修飾する](https://developers.google.com/search/docs/crawling-indexing/qualify-outbound-links)選択肢を与えない)
- ランキングクレジットを渡すテキスト広告やテキストリンク
- 他のサイトに配布される記事、ゲスト投稿、プレスリリースでの、支払いを受けた記事や最適化されたアンカーテキストを含むリンク
- 低品質のディレクトリやブックマークサイトのリンク
- さまざまなサイトに配布されるウィジェットに埋め込まれた、キーワードが豊富で、隠れた、または低品質のリンク
- さまざまなサイトのフッターまたはテンプレートに広く配布されたリンク
- 投稿または署名に最適化されたリンクを含むフォーラムコメント

**ポリシー違反ではないもの:**
- [rel="nofollow"](https://developers.google.com/search/docs/crawling-indexing/qualify-outbound-links#nofollow)または[rel="sponsored"](https://developers.google.com/search/docs/crawling-indexing/qualify-outbound-links#sponsored)属性で修飾されたリンク

#### 8. Machine-Generated Traffic (機械生成トラフィック)

**定義:**
Googleに自動化されたクエリを送信する行為(ランクチェック目的でのスクレイピング、明示的な許可なしのGoogle検索への自動化されたアクセスなど)。

#### 9. Malware and Malicious Practices (マルウェアと悪意のある行為)

**Malware (マルウェア):**
コンピュータ、モバイルデバイス、実行中のソフトウェア、またはそのユーザーに害を与えることを特に設計されたソフトウェアまたはモバイルアプリケーション。

**Unwanted Software (不要なソフトウェア):**
欺瞞的、予期しない、またはユーザーのブラウジングやコンピューティング体験に悪影響を与える動作を行う実行可能ファイルまたはモバイルアプリケーション。

#### 10. Misleading Functionality (誤解を招く機能)

**定義:**
ユーザーをだまして、実際にはできないコンテンツやサービスにアクセスできると思わせるサイトを意図的に作成する行為。

**例:**
- アプリストアクレジットを提供すると主張するが、実際には提供しない偽のジェネレーター
- 特定の機能(PDF結合、カウントダウンタイマー、オンライン辞書サービスなど)を提供すると主張するが、意図的にユーザーを欺瞞的な広告に誘導するサイト

#### 11. Scaled Content Abuse (大規模コンテンツの不正使用)

**定義:**
検索ランキングを操作する主な目的で多くのページが生成される場合。この不正な行為は、通常、ユーザーにほとんどまたはまったく価値を提供しない大量のオリジナルでないコンテンツを作成することに焦点を当てている。

**例:**
- ユーザーに価値を追加せずに、生成AIツールまたは他の同様のツールを使用して多くのページを生成
- フィード、検索結果、または他のコンテンツをスクレイピングして多くのページを生成(自動変換を通じて)
- 異なるWebページのコンテンツをつなぎ合わせたり組み合わせたりする(価値を追加せずに)
- コンテンツの大規模な性質を隠す意図で複数のサイトを作成
- 読者にはほとんどまたはまったく意味をなさないが、検索キーワードを含む多くのページを作成

#### 12. Scraping (スクレイピング)

**定義:**
検索ランキングを操作する目的で、多くの場合自動化された手段を通じて、他のサイトからコンテンツを取得し、ホストする行為。

**例:**
- オリジナルのコンテンツや価値を追加せずに、他のサイトからコンテンツを再公開
- 他のサイトからコンテンツをコピーし、わずかに変更(類義語の置き換えや自動化された技術の使用)して再公開
- 何らかのユニークな利益をユーザーに提供せずに、他のサイトからコンテンツフィードを再現
- ユーザーに実質的な付加価値を提供せずに、他のサイトからのビデオ、画像、またはその他のメディアの埋め込みまたはコンパイル専用のサイトを作成

#### 13. Site Reputation Abuse (サイト評判の不正使用)

**定義:**
サードパーティのコンテンツが、主にホストサイトのすでに確立されたランキングシグナル(主にファーストパーティコンテンツから得られた)のためにホストサイトに公開される戦術。この戦術の目標は、コンテンツが単独でランク付けできるよりも良くランク付けすることです。

**例:**
- 教育サイトが、サードパーティによって書かれたペイデイローンのスポンサーレビューに関するページをホスティング
- 医療サイトが「最高のカジノ」に関するサードパーティ広告ページをホスティング
- 映画レビューサイトが、映画レビューサイトで見つけることをユーザーが混乱するトピックに関するサードパーティページをホスティング
- ニュースサイトが、サードパーティのホワイトレーベルサービスによって提供されたクーポンをホスティング

**ポリシー違反ではないもの:**
- ワイヤーサービスまたはプレスリリースサービスサイト
- 他のニュース出版物からシンジケートされたニュースコンテンツを持つニュース出版物
- ユーザー生成コンテンツを許可するように設計されたサイト(フォーラムWebサイトやコメントセクションなど)
- コラム、オピニオン記事、記事、その他編集的性質の仕事
- 読者と直接コンテンツを共有する目的のサードパーティコンテンツ(検索ランキングを操作するためにコンテンツをホスティングするのではなく)
- ページ全体でアフィリエイトリンクを使用(リンクを適切に扱う)、またはページ全体にサードパーティ広告ユニットを埋め込む
- 商人や消費者にサービスを提供する他のビジネスから直接調達されたクーポン

#### 14. Sneaky Redirects (隠しリダイレクト)

**定義:**
ユーザーまたは検索エンジンに異なるコンテンツを表示したり、ユーザーの元のニーズを満たさない予期しないコンテンツを表示したりするために、悪意を持ってリダイレクトを行う行為。

**例:**
- 検索エンジンには1つのタイプのコンテンツを表示し、ユーザーを大幅に異なるものにリダイレクト
- デスクトップユーザーには通常のページを表示し、モバイルユーザーを完全に異なるスパムドメインにリダイレクト

**正当なリダイレクト:**
- サイトを新しいアドレスに移動
- 複数のページを1つに統合
- ログイン後にユーザーを内部ページにリダイレクト

#### 15. Thin Affiliation (薄いアフィリエイト)

**定義:**
製品のアフィリエイトリンクを含むコンテンツを公開し、製品の説明とレビューがオリジナルのコンテンツや付加価値なしに元の商人から直接コピーされている行為。

**良いアフィリエイトサイトの例:**
- 価格に関する追加情報
- オリジナルの製品レビュー
- 厳密なテストと評価
- 製品またはカテゴリのナビゲーション
- 製品の比較

#### 16. User-Generated Spam (ユーザー生成スパム)

**定義:**
ユーザーコンテンツ用のチャネルを通じてユーザーによってサイトに追加されたスパムコンテンツ。

**例:**
- 誰でも登録できるホスティングサービスのスパムアカウント
- フォーラムスレッドのスパム投稿
- ブログのコメントスパム
- ファイルホスティングプラットフォームにアップロードされたスパムファイル

## 7. Page Experience (ページエクスペリエンス)

**公式ドキュメント:** https://developers.google.com/search/docs/appearance/page-experience

### Page Experienceとは

Googleのコアランキングシステムは、良いページエクスペリエンスを提供するコンテンツを報酬として与えるように設計されている。

**重要な原則:**
1つまたは2つのページエクスペリエンスの側面のみに焦点を当てるのではなく、多くの側面にわたって全体的に優れたページエクスペリエンスを提供しているかどうかを確認する。

### 自己評価質問

以下の質問に「はい」と答えることは、良いページエクスペリエンスを提供している可能性が高い:

1. ページは良好なCore Web Vitalsを持っているか?
2. ページは安全な方法で提供されているか?
3. コンテンツはモバイルデバイスでよく表示されるか?
4. コンテンツは、メインコンテンツから気をそらしたり妨げたりする過度な量の広告を使用していないか?
5. ページは侵入的なインタースティシャルの使用を避けているか?
6. ページは、訪問者がメインコンテンツを他のコンテンツと簡単に区別できるように設計されているか?

### FAQ

**単一の「ページエクスペリエンスシグナル」はあるか?**
いいえ、単一のシグナルはありません。コアランキングシステムは、全体的なページエクスペリエンスと一致するさまざまなシグナルを見ています。

**ランキングにはどのページエクスペリエンスの側面が使用されるか?**
- Core Web Vitalsはランキングシステムで使用されている
- Core Web Vitalsを超える他のページエクスペリエンスの側面は、Webサイトのランキングを直接向上させない
- ただし、より満足のいく使用体験を提供できる(これはランキングシステムが報酬を与えようとするものと一般的に一致)

**ページエクスペリエンスはサイト全体またはページ固有で評価されるか?**
- コアランキングシステムは、一般的にページ固有ベースでコンテンツを評価
- ただし、サイト全体の評価もいくつかある

**ランキング成功にとってページエクスペリエンスはどれほど重要か?**
- Google検索は常に最も関連性の高いコンテンツを表示しようとする(ページエクスペリエンスが劣悪でも)
- ただし、多くのクエリには役立つコンテンツがたくさんある
- そのような場合、優れたページエクスペリエンスを持つことは検索での成功に貢献できる

## 8. Core Web Vitals (コアウェブバイタル)

**公式ドキュメント:** https://developers.google.com/search/docs/appearance/core-web-vitals

### Core Web Vitalsとは

ページの読み込みパフォーマンス、インタラクティビティ、視覚的安定性に関する実際のユーザー体験を測定する一連の指標。

**重要性:**
- 検索での成功に推奨
- 一般的に優れたユーザー体験を保証
- 他のページエクスペリエンスの側面と共に、コアランキングシステムが報酬を与えようとするものと一致

### Core Web Vitals指標

#### 1. Largest Contentful Paint (LCP) - 最大コンテンツの描画

**測定対象:**
読み込みパフォーマンス

**目標:**
ページの読み込み開始から**2.5秒以内**にLCPが発生すること

**定義:**
ビューポート内で最も大きなコンテンツ要素(画像、ビデオ、テキストブロックなど)が画面にレンダリングされるまでの時間。

#### 2. Interaction To Next Paint (INP) - 次の描画までのインタラクション

**測定対象:**
応答性

**目標:**
**200ミリ秒未満**のINP

**定義:**
ユーザーがページとインタラクト(クリック、タップ、キー入力)してから、次の視覚的更新(ペイント)が発生するまでの時間。

#### 3. Cumulative Layout Shift (CLS) - 累積レイアウトシフト

**測定対象:**
視覚的安定性

**目標:**
**0.1未満**のCLSスコア

**定義:**
ページのライフサイクル中に発生する予期しないレイアウトシフトの累積スコア。
