3. 課題

3.1 技術的課題

最優先

3.1.1 インデックス数の異常

現象: 9ページ中4ページのみインデックス

原因（推定）: 1. Wixの重いJavaScriptでレンダリング遅延 2. 古いNGOコンテンツとの混在でクロールバジェット消費 3. 内部リンク構造が弱い

影響: - ページが検索結果に表示されない - ランキング機会の損失 - トラフィック獲得不可

3.1.2 タイトル・メタの最適化不足

現状のタイトル:

「ETA申請：UK ETA application site」

問題点: - 全角コロン（：）→ 不自然 - 差別化要素なし（「フランス語」に言及なし） - キーワード不十分 - ブランド名なし - 魅力に欠ける

影響: - クリック率（CTR）低下 - ランキング不利 - ブランド認知度低

3.1.3 古いNGOコンテンツの残存

問題:

古いページ（NGO関連）が残存
→ トピック混乱（ETA申請 vs 青少年育成）
→ Googleが正しく評価できない
→ インデックス・ランキングに悪影響

優先度: 即削除必要

高優先

3.1.4 PageSpeed最適化の限界

Wixの制約: - サーバー制御不可 - 画像最適化の自由度低い - 不要なWixスクリプト削除不可 - コード圧縮の制御不可

影響: - PageSpeed 60～70止まり（推定） - Core Web Vitals不良 - モバイルSEOで不利（2021年～ランキング要因）

3.1.5 構造化データの制約

Wixの制限: - カスタム構造化データ追加困難 - FAQ、レビュー評価等の柔軟性低い

影響: - リッチスニペット取得困難 - CTR向上機会の損失

3.2 コンテンツ課題

最優先

3.2.1 差別化の明確化不足

問題: 「なぜ公式サイト（16ポンド）ではなく、当サービス（75ポンド）を使うべきか？」が不明確

影響: - コンバージョン率低下 - 競合に流れる - 価格抵抗

3.2.2 信頼性の証明不足

欠けているもの: - 顧客レビュー・評価 - 成功事例 - 処理件数の実績 - メディア掲載（あれば）

影響: - 信頼性低下 - コンバージョン率低下

高優先

3.2.3 ブログ/記事コンテンツなし

問題: - 情報検索ユーザーを獲得できない - ロングテールキーワード対策不可 - 内部リンク構築機会損失

影響: - SEOトラフィック限定的 - 競合に流れる

3.2.4 FAQ不十分

現状: 基本的なFAQのみ

欠けている重要FAQ: - 「英語が話せません。それでもETA申請できますか？」 - 「なぜ75ポンド払う必要があるのですか？公式サイトは16ポンドですが」 - 「御社のサービスと公式サイトの違いは何ですか？」

影響: - ユーザーの不安解消できず - コンバージョン率低下 - 質問型キーワードで順位取れず

3.3 プラットフォーム課題

中期的課題

3.3.1 Wixの技術的限界

制約: - JavaScript重い → インデックス遅延 - PageSpeed最適化困難 → ランキング不利 - 構造化データ制約 → リッチスニペット困難 - コード制御不可 → 高度最適化不可

影響: - 上位表示の限界（10～15位止まりの可能性） - 競合（WordPress使用）に技術で劣る

解決策: WordPress/Next.js移行（中期）

3.4 競合環境課題

緊急

3.4.1 競合の急成長

事実: - 新規ドメイン（2～3ヶ月）が既に2～10位 - 同じ戦略（フランス語）を実行中 - uk-eta.fr（WordPress）が2位達成

脅威: - 競合が市場シェアを先取り - ドメインエイジが進むほど追いつくのが困難 - 今動かないと手遅れ

9. リスクと対策

9.1 SEOリスク

9.1.1 競合の更なる成長

リスク:

競合（特にuk-eta.fr）がドメインエイジを重ね、
さらに上位に → 追い越せなくなる

影響度: 高
発生確率: 中

対策: 1. スピード重視（今すぐPhase 1開始） 2. 質で勝負（競合より詳細なコンテンツ） 3. 技術で上回る（Next.js移行時） 4. 実績強調（15,000+件等、数字で差別化）

9.1.2 Googleアルゴリズム変更

リスク:

アップデートで順位大幅下落

影響度: 中
発生確率: 中（年数回）

対策: 1. ホワイトハットSEO徹底（ペナルティリスクなし） 2. E-E-A-T強化（専門性、権威性、信頼性） 3. コンテンツ品質優先（ユーザー第一） 4. 分散（複数キーワードでランクイン）

9.1.3 インデックス問題の継続

リスク:

Phase 1実施後もインデックス数が増えない

影響度: 高
発生確率: 中（Wix特有の問題）

対策: 1. 古いコンテンツ完全削除（最優先） 2. サイトマップ最新化・再送信 3. URL検査で手動インデックス 4. 解決しない場合 → Phase 2前倒し

9.2 プラットフォーム移行リスク

9.2.1 ダウンタイム

リスク:

移行中にサイトが停止 → トラフィック損失、ランキング低下

影響度: 高
発生確率: 低（対策済み）

対策: 1. テスト環境で完全構築 2. DNS切替のみ（数分） 3. 深夜実施（トラフィック少ない時間） 4. ロールバック計画（問題時は即Wixに戻す）

9.2.2 URL変更によるランキング損失

リスク:

移行後、一時的に順位低下

影響度: 中
発生確率: 中（一時的）

対策: 1. URL構造維持（同じパス） 2. 301リダイレクト完璧設定 3. Google Search Consoleで移行通知 4. 通常1～2週間で回復（Googleが認識）

9.2.3 コンテンツ損失

リスク:

移行中にコンテンツが欠落

影響度: 高
発生確率: 低（対策済み）

対策: 1. Wix完全バックアップ（事前） 2. 段階的移行（ページごと確認） 3. チェックリスト（全要素確認） 4. 移行後検証（全ページ手動確認）

9.3 ビジネスリスク

9.3.1 予算超過

リスク:

移行費用が見積もりを超える

影響度: 中
発生確率: 中

対策: 1. 固定価格契約（外注時） 2. 段階的支払い（マイルストーン） 3. Phase 1で効果検証（移行前にROI確認） 4. 予備費確保（見積もり+20%）

9.3.2 期待効果未達

リスク:

投資したが期待した順位・トラフィックに届かない

影響度: 高
発生確率: 中

対策: 1. 現実的な目標設定（公的機関は超えられない） 2. 段階的アプローチ（Phase 1で検証） 3. 継続的改善（Phase 3で最適化継続） 4. 複数キーワード戦略（1つに依存しない）
